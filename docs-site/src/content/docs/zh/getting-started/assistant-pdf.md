助手可以阅读 PDF——论文、支持信息（SI）或软件手册——并利用其中的内容，例如复现
论文报告的理论级别或 MD 参数。该功能适用于所有模型提供方：Claude 和 GPT 模型收到
的是附加的 PDF 本身，其他模型收到的是 SilicoLab 在本地提取的文本。

## 让助手读一个 PDF

把 PDF 拖到 SilicoLab 窗口上，或点击助手输入框里的回形针按钮选择文件。PDF 会以卡片
形式出现在输入框中——鼠标悬停后点击 × 即可移除——每条消息最多附加五个。写下你想让助手
做什么，然后发送。也可以自己输入路径：

```text
阅读 refs/zhang2024.pdf，告诉我他们做几何优化时用了什么泛函、基组和色散校正。
```

发送之后，附加的 PDF 会以卡片形式留在那条消息上，并随对话一起按引用保存：SilicoLab
记录的是文件位置，而不是文件副本。之后即使你移动或删除了文件，对话仍可正常打开，助手
会被告知该附件已不可用。

如果你是输入路径而不是附加文件，读取会在后台进行。文本返回后助手才会作答，对话中会
出现一条 **Background PDF read** 提示标记这一时刻。

长文档每次只读取若干页。对于长论文或 SI，请提出有针对性的问题：助手可以先在
文档中搜索某个词，再只阅读提到它的页面。让助手注明页码，便于你对照原文核对数值。

## 模型实际收到什么

| 模型 | 附加的 PDF 以何种形式送达 |
| --- | --- |
| Anthropic（Claude）、OpenAI（GPT）——使用提供方自己的端点 | PDF 本身，因此模型也能看到图片、图片形式的表格和扫描页。 |
| Gemini、DeepSeek、GLM、OpenRouter、本地和自定义端点，或任何改写了 base URL 的提供方 | 在你电脑上提取出的文本。对话中会出现一次性提示说明这一点。 |
| Claude CLI、Codex CLI | 文件路径；CLI 自己从磁盘读取。 |

直接发送 PDF 的成本更高：对话中的每次请求都会重新上传它，Claude 每页约计 1,500–3,000
个 token；在 Claude 上，提示缓存会让同一轮里的后续请求便宜很多。为控制开销，只有最近
两条带附件的消息会完整发送，更早的附件会缩减为一条引用，助手需要时再按页重新读取。

超过提供方限制的 PDF——Claude 为 100 页或每次请求约 22 MB，GPT 约 36 MB——会改为
发送提取文本，并告知模型原因。

## 文件位置决定是否需要确认

| 路径 | 行为 |
| --- | --- |
| 你自己选定的任何文件——作为附件添加，或在消息中输入路径 | 直接读取，不询问。 |
| 位于项目文件夹内，并以相对路径给出（`refs/paper.pdf`） | 直接读取，不询问。 |
| 助手自行选择的其他位置（绝对路径，或包含 `..` 的路径） | 在 **Manual** 和 **Auto (safe)** 模式下显示为 **outside-project read**，需你先批准；**Auto** 模式下不询问直接读取。 |

PDF 或其提取文本会和对话的其余内容一样发送给你的模型提供方。请把要用的论文放在项目
文件夹内，不要让助手读取你自己不会粘贴进聊天的文档。

## 限制

以下限制适用于模型收到的是提取文本而非 PDF 本身的情况：

- 扫描版 PDF 没有文本层，无法读取；不支持 OCR。
- 图片，以及以图片形式存在的表格，模型看不到。文本表格会以纯文本形式返回，可能
  丢失列对齐——请对照 PDF 核对提取出的数字。

以下限制始终适用：

- 无法打开受密码保护的 PDF。
- 超过 64 MB 或 2000 页的文件会被拒绝。
